# Computer Use Agent 完整產品與開發規劃 v1.0

**規劃日期：2026-09-11｜語言：繁體中文｜126項工作｜21階段｜60類驗收測試**

> 這是擬定的開發與驗收規格，不代表功能已實作或已在你的電腦實測。P00–P19共120項為桌面產品v1.0範圍；P20共6項為設備／研究獨立選配。所有測試數字為建議門檻，不是實測成績。

## 1. 最終產品

一套Windows優先、本地優先、模型可替換的個人Computer Use Agent。使用者以文字或語音交代結果；系統自主規劃，依授權選擇GUI、瀏覽器、檔案、終端或API，透過獨立完成規則驗證結果。使用者可在過程中修改限制、暫停、停止、接管，再交還執行。支援有界長任務、多Worker分工、主動示範教學與至少一條配對遠端Windows工作路線。

### 產品界線

不是固定座標巨集；不是全靠滑鼠的表演；不是把多個外部Agent各自啟動後稱為整合。只有一個正式入口、一份權威任務狀態、一個動作執行邊界。各框架都是內部能力來源。宣稱支援的功能必須通過對應矩陣，不承諾任意軟體或任意模型百分之百成功。

Windows 11受支援版本作主要基線；Windows 10按實際版本、安全更新／ESU／LTSC條件保留相容性測試。Windows 10 Home/Pro一般支援於2025-10-14結束，來源見S11。macOS/Linux控制節點逐項驗證；以Mac作控制台操作遠端Windows，和Agent直接操作Mac，是不同支援項。

## 2. 核心架構

```text
文字／語音／示範／人工接管
               ↓
桌面控制台（真實事件、任務板、畫面、授權）
               ↓
Supervisor + 唯一 TaskStore / EventStore
               ↓
Hermes 主要決策迴圈（先沿用，不預設後期重寫）
               ↓
動態計畫 / 工具選擇 / 子任務分工
               ↓
Policy + Approval + ResourceLease + ActionGateway
               ↓
桌面Cua / 瀏覽器 / 檔案與受管Shell / 遠端Worker
               ↓
Observation → Evidence → Verifier
               ↓
狀態提交／有限重試／重規劃／等待使用者／最終交付

本機停止控制：獨立於模型，直接撤銷租約與阻擋新動作。
```

規劃、執行、驗證是責任分離，不代表一定要三個不同模型。相同模型可依序兼任不同角色；完成裁決仍須依據可重複檢查與外部證據。多個模型互相同意也不代表事實正確。

第一版採一個主模型；額外定位模型按需。以你現有本地GPU做實測資源調度，不預設同時常駐多個大模型。UI、語音、Worker等不得另設不受控的動作出口。

### 任務狀態機

```text
DRAFT → QUEUED → PLANNING → READY → RUNNING → VERIFYING → SUCCEEDED
                            │        │          ├→ FAILED
                            │        │          └→ INCONCLUSIVE
                            │        ├→ WAITING_APPROVAL / WAITING_USER
                            │        ├→ PAUSED → REOBSERVE → READY
                            │        ├→ BLOCKED → REPLAN / WAITING_USER
                            │        └→ RECONCILING（副作用結果不明，先對帳）
                            └──────────→ CANCELLING → CANCELLED
```

取消只阻止可取消的未來動作，不代表已寄送內容、付款或外部系統變更會被撤回。取消時仍有未決副作用，必須在狀態或副作用帳本中明示，完成對帳後才結案。不可逆副作用沒有通用rollback；檔案、分支等可逆操作才實作補償。

### 每一步的最小執行合約

先檢查任務版本、完成條件、授權、精確核準內容、資源租約和觀察版本；再執行具型別動作；重新觀察並驗證；最後提交狀態。模型生成的任意程式不能直接exec。操作被某工具拒絕後，換Shell、API或MCP仍受同一政策約束。

## 13. 每個工作項目的完成定義

完成項目必須具備：對應ID的實作與差異；最小重現與測試；真實驗證輸出；對應設定和文件；取消／失敗分支；更新支援與限制矩陣；不含秘密或多餘資料的證據。新增功能不能默默增加權限、把安全測試關掉、靠硬編碼特例讓測試過，或把未執行測試寫成通過。

Excel的已完成數只是進度統計，不會自動授予發布資格。階段和發布Gate必須由實測證據確認；表格初始待盤點不表示你現有環境沒有已完成能力。
