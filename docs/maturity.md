# 如何判斷這個專案是否成熟

最終目標是廣泛、可靠地完成電腦操作；模型接頭、滑鼠能動、漂亮介面都不足以證明達標。使用者指定的小模型是實際驗收對象，不能在測試失敗時改用強模型代打，再宣稱小模型成功。

詳細驗收依 [完整規劃](plans/Computer_Use_Agent_Full_Plan_v1.0.md)、[60 類驗收與 Gate](../ACCEPTANCE.md)。新增的硬性要求是代理擁有自己的輸入，不得搶使用者的滑鼠、鍵盤焦點或剪貼簿。舊版全域輸入測試不能認證這項要求；原生桌面執行目前停用。

## 證據層次

| 證據 | 能證明什麼 | 不能證明什麼 |
| --- | --- | --- |
| API／單元測試 | 格式、取消、狀態轉移、座標核對的已覆蓋行為 | 模型能完成任務 |
| 固定腳本自我檢查 | 驅動和介面確實連通 | AI 規劃能力 |
| 真實模型＋獨立 oracle | 該次任務確實產生指定最終狀態 | 任意網站或任意應用程式皆可成功 |
| 多次、變體、未見過的任務 | 對變化的穩定性和泛化能力 | 尚未覆蓋的領域 |

規劃模型關閉影像輸入時，只收到文字及元素資訊。這能驗證不依賴規劃模型看圖的管線；MiniCPM 與 Qwen3-VL 本身都是多模態模型，仍需額外的純文字模型測試才能比較模型能力。

## 必須逐項擴充的驗收範圍

| 領域 | 應驗證的結果 |
| --- | --- |
| 表單與選單 | 正確欄位、值、勾選狀態；錯誤不得漏報 |
| 查找與資料修改 | 多筆資料中選對對象，只改指定內容 |
| 跨分頁 | 從實際頁面取得資料，正確保留並填回 |
| 原生桌面 | 正確視窗、Unicode 輸入、快捷鍵、儲存後內容 |
| 檔案工作 | 上傳內容與下載檔案符合任務，路徑和檔名可追溯 |
| OCR-only | 移除 DOM／AX 語意後仍可辨識與定位所需操作 |
| 圖示與自繪介面 | 缺乏文字時的定位，不以預設座標冒充辨識 |
| 中斷與復原 | 暫停、人工操作、重新觀察、錯誤修正及停止 |
| 長任務 | 進度不遺失，未完成部分能明確指出 |
| 泛化 | 改文字、版面、資料、尺寸及流程後維持成功率 |

可執行基準見 `benchmarks/README.md` 和 `benchmarks/native.md`。報告保留實際操作、錯誤、耗時、最終資料與 oracle 結果。修改提示或執行方式後要產生新報告，不能覆寫失敗證據或修改成功條件來提高分數。

## 接下來的成熟門檻

先在指定的兩個規劃模型上分別完成相同的基本任務矩陣；GLM-OCR 以獨立感知角色驗證。通過後增加未見過的介面、任務變體、重複測試與失敗復原。應同時公布成功率、模型誤報完成率、人工介入次數、延遲及動作數。

目前沒有 GPT-6 Astra 在這套相同任務與限制下的對照成績，因此不能宣稱等效。最終目標保留；實際能力以可重現證據逐步建立。
